# Updating screenshots

The README screenshots in `docs/screenshots/` are generated by a script, `scripts/take-screenshots.ts`. It starts the client's dev server, opens the app in headless Chromium at iPhone size (390×844 at 3×, so 1170×2532 images), clicks through each screen, and saves `<Screen>-<client version>.png`.

Every `/api` request is answered inside the browser with made-up data: a fake NAS (`192.168.1.20`, user `reader`, share `books`), a fake folder listing and a canned chat reply. No server, NAS, credentials or Anthropic API key is used, so nothing private can end up in an image, and the chat screenshot costs nothing.

## One-time setup

1. Use the Node version from `.nvmrc` (`nvm use`). pnpm 11 doesn't start on older Node.
2. Install dependencies: `pnpm install`.
3. Download the browser Playwright drives (about 100 MB, stored outside the repo in Playwright's cache):

   ```bash
   pnpm exec playwright install chromium
   ```

The two books the screenshots show are public domain and committed in `scripts/books/`, so there's nothing to download. [scripts/books/README.md](../scripts/books/README.md) lists where each one comes from.

## Taking screenshots

```bash
pnpm screenshots
```

Then:

1. Look through the new images. The script uses whatever the app currently renders, so check for anything unexpected.
2. Delete the previous version's images: `rm docs/screenshots/*-<old version>.png`.
3. Point the README's `<img>` tags at the new version, e.g. `sed -i '' 's/-<old version>\.png/-<new version>.png/g' README.md`.

## Adding or changing a screen

Each screen is a short block in `main()` in `scripts/take-screenshots.ts`: navigate or click to the state, then `capture({ page, name })`. If the screen calls a new `/api` endpoint, add a fake response for it in `answerApiRequest`. Add the new image to the README's screenshot list.

## Gotchas

- Route fakes match `/api/` at the start of the path. A `**/api/**` pattern would also catch the dev server's source files under `src/lib/api/` and break the app.
- Footnote links render with zero height, so Playwright treats them as hidden. The script finds them by position and dispatches the click directly.
- Before each capture the script moves the mouse away and clears focus, so no hover highlight or focus ring shows up in the image.
